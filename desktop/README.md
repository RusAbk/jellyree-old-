# Jellyree Desktop

Отдельный клиент на Electron + Vue для личного диска в Cloudflare. Приложение не использует `server/`, Prisma, MySQL, JWT или развёрнутый Worker. Файлы хранятся в R2, папки и метаданные — в D1. В настройках вводятся ваши реквизиты Cloudflare.

## Запуск

Нужен Node.js 22.13+ (рекомендуется 24) и npm. Зависимости desktop устанавливаются отдельно от корневых workspaces:

```bash
cd desktop
npm ci
npm run dev
```

Для запуска собранного интерфейса:

```bash
npm run build
npm start
```

В режиме разработки Vite слушает `127.0.0.1:5174`. Это только dev-инструмент: собранное приложение открывает локальные файлы и не запускает HTTP-сервер.

Если Linux останавливает Electron с ошибкой настройки `chrome-sandbox`, для локального dev-запуска доступна команда `npm run dev -- --no-sandbox`. Флаг отключает Chromium sandbox только для этого запуска.

Из корня репозитория доступны `npm run dev:desktop`, `npm run build:desktop`, `npm run test:desktop`, `npm run dist:desktop` после установки зависимостей в `desktop/`.

## Язык интерфейса

Доступны **English**, **Русский** и **Español**. По умолчанию используется английский независимо от языка ОС. Переключатель находится в верхней панели и в окне подключения Cloudflare; выбор сохраняется на устройстве. Переведены интерфейс, контекстные меню, диалоги загрузки, сообщения приложения и меню Electron. Имена пользовательских файлов, папок и тегов не переводятся. Системные элементы нативного файлового диалога могут использовать язык ОС.

## Подключение Cloudflare

1. Создайте bucket в **R2 Object Storage**. Публичный доступ включать не нужно.
2. Создайте **R2 API token** с правами **Object Read & Write** для этого bucket. Сохраните S3 **Access Key ID** и **Secret Access Key**. Это отдельные реквизиты, отличные от API token для D1.
3. Создайте базу в **Workers & Pages → D1 SQL Database**. Скопируйте **Database ID**.
4. Создайте Cloudflare API token с правом **Account → D1 → Edit** (D1 Write) для нужного аккаунта.
5. Откройте настройки приложения. Введите Account ID, Database ID, API token, имя bucket и S3-реквизиты R2.
6. При необходимости задайте префикс объектов (по умолчанию `jellyree`). Нажмите **Проверить подключение**, затем **Сохранить и открыть**.

Проверка выполняет `SELECT 1` в D1 и `HeadBucket` в R2. При сохранении приложение создаёт свои таблицы `jr_folders`, `jr_files` и индексы через `CREATE ... IF NOT EXISTS`. Остальные таблицы не изменяются. Один каталог соответствует сочетанию Account ID + bucket + prefix; при смене bucket или prefix показывается другой каталог. На нескольких устройствах используйте одну D1 и одинаковые bucket/prefix. Обновление между устройствами — кнопкой обновления, без live-синхронизации.

Реквизиты остаются в основном процессе Electron. Файл подключения `jellyree-cloud/connection.enc` в каталоге `userData` зашифрован через Electron `safeStorage`. На Linux требуется доступное системное хранилище секретов. Если его нет или выбран `basic_text`, приложение работает с реквизитами в памяти и просит ввести их снова после закрытия. Открытого JSON с ключами и ключей в `localStorage` нет. Функция «Забыть подключение» удаляет локальные реквизиты; облачные данные остаются.

## Возможности

- Загрузка файлов через системный диалог и drag-and-drop; загрузка целых папок с сохранением вложенности, включая пустые папки.
- Потоковая multipart-загрузка в R2 выполняется в фоне: можно переходить между папками, искать, просматривать, переименовывать и скачивать файлы. Кнопка **Uploads / Загрузки / Subidas** открывает сворачиваемую панель с очередью, прогрессом и результатами каждой пачки. Новые пачки последовательно загружаются в выбранные при добавлении папки. Ошибки и предупреждения остаются в панели; завершение не меняет текущую папку, выделение и загруженные страницы каталога. Оставляйте приложение открытым до завершения передачи; продолжение передачи после перезапуска не реализовано.
- Вложенные папки: создание, переименование, перенос с проверкой циклов; удаление пустых папок.
- Перетаскивание файла или нескольких выделенных файлов на карточку папки, в боковое дерево, на «Мой диск» или в хлебные крошки перемещает их в выбранную папку. Так же можно переносить папки; перенос внутрь себя или своего потомка запрещён. Перетаскивание файлов с компьютера на папку загружает их сразу в неё.
- Три вида: сетка, список и галерея с исходными пропорциями изображений без обрезки, включая повёрнутые кадры. Размер превью регулируется ползунком от 120 до 420 px; вид и размер сохраняются на устройстве. Сортировка по имени/размеру/дате, постраничная загрузка по 80 файлов.
- Контекстные меню файлов, папок в каталоге и дереве, свободного места. Правый клик по выбранному файлу сохраняет массовое выделение. Меню папки позволяет загрузить файлы прямо в неё и создать вложенную папку. Доступны управление стрелками, Shift+F10 и закрытие по Escape.
- Поиск по именам и тегам в текущем разделе. В «Моём диске» поиск файлов ограничен текущей папкой; для поиска по всему каталогу выберите «Все файлы».
- Теги, избранное, фото и видео, панель информации; массовый перенос, теги, скачивание и корзина.
- Просмотр поддерживаемых Chromium изображений, видео и аудио. Другие форматы можно скачать. Стрелки переключают загруженные файлы, Escape закрывает просмотр.
- Миниатюры видео показывают кадр и длительность; в галерее сохраняются исходные пропорции. Кадры извлекаются без звука по временной ссылке R2 только возле видимой области, максимум тремя декодерами одновременно. После получения кадра видеопоток освобождается. Сервер, ffmpeg и настройка CORS bucket для этого не нужны. Неподдерживаемые Chromium кодеки показывают сообщение о недоступном превью. Миниатюры сохраняются в локальном дисковом кэше.
- Редактор фото с тоновыми, цветовыми и детальными настройками, кадрированием, пластикой, растяжением и экспортом обработанной копии. Правки сохраняются в D1 и применяются в просмотре и миниатюрах; оригинал в R2 сохраняется. Кнопка скачивания оригинала возвращает исходный файл.
- Корзина без автоматического удаления: восстановление либо явное окончательное удаление из R2 и D1.
- Временная ссылка на оригинал R2 на один час, с копированием в буфер обмена. Серверные публичные страницы альбомов, пароли для ссылок, учётные записи пользователей и администрирование в этот клиент не перенесены.
- `Ctrl/Cmd+A` выбирает загруженные файлы; Delete перемещает выбранные в корзину.

Скачивание нескольких файлов сохраняет их в выбранную локальную папку; совпадающие имена получают числовой суффикс. Это не ZIP-архив. Массовое назначение тегов заменяет текущие теги выбранных файлов.

## Видео: скорость и стопкадры

В просмотре видео доступны скорости **0.25×, 0.5×, 0.75×, 1×, 1.25×, 1.5×, 2×**. Выбор сохраняется на устройстве и применяется к следующим видео. Нативные средства воспроизведения, звука и перемотки остаются доступны; отдельная кнопка полноэкранного режима сохраняет панель скорости и стопкадров на экране.

- **Save frame to folder / Сохранить кадр в папку** захватывает текущий показанный кадр в PNG с исходным разрешением видео и создаёт новый файл в той же папке R2/D1. Имя содержит позицию с миллисекундами; повторный снимок получает числовой суффикс. Видео и существующие файлы не изменяются. Если идут другие загрузки, передача кадра ожидает их в общей очереди. Можно продолжать просмотр или закрыть плеер — начатое сохранение завершится в фоне.
- **Download frame / Скачать стопкадр** сохраняет PNG на компьютере через системный диалог. Отмена диалога ничего не создаёт.
- Пробел запускает и останавливает видео; ←/→ перематывают на 5 секунд, Ctrl+↑/↓ меняют скорость, Shift+S сохраняет кадр в папку, когда фокус находится в плеере.

PNG фиксируется сразу при нажатии, поэтому дальнейшее воспроизведение или перемотка не меняет выбранный кадр. Для захвата используется локальный потоковый протокол Electron, без настройки CORS и без ffmpeg. Для длинных сессий Range-запросы получают свежие подписанные ссылки R2. Кнопки стопкадра доступны после загрузки кадра и завершения перемотки. Поддерживаются кадры до 40 Мп.

## Документы: PDF, TXT и Markdown

Двойной щелчок по PDF, TXT, MD или Markdown открывает встроенный просмотр. Распознаются расширения файлов (без учёта регистра) и MIME-типы, в том числе у объектов, импортированных из R2 с типом `application/octet-stream`.

- **PDF**: переключение страниц, ввод номера страницы, масштаб 50–300%, подгонка по ширине окна и выделение текста. Поддерживается ввод пароля защищённых PDF. Рисуется текущая страница; при закрытии освобождаются canvas и worker.
- **TXT**: поиск с подсветкой и переходом между совпадениями (Ctrl/Cmd+F), перенос строк, размер шрифта и выбор UTF-8, UTF-16 LE/BE, Windows-1251 или Windows-1252. Режим Auto распознаёт BOM UTF-16 и иначе использует UTF-8.
- **Markdown**: заголовки, списки, таблицы, цитаты, блоки кода и переключение на исходный текст с поиском. Вложенный HTML очищается; скрипты, формы и удалённые изображения не выполняются и не загружаются. Ссылки не открывают сторонние страницы из просмотрщика.

Кнопка **Edit / Редактировать / Editar** открывает редактор TXT или Markdown с номерами строк, поиском и заменой, переходом к строке, отменой/повтором, настройками переноса и размера текста. В Markdown есть подсветка синтаксиса, панель форматирования и живой предпросмотр рядом с исходником; кнопка **Preview / Предпросмотр / Vista previa** выключает и включает его, выбор сохраняется на устройстве.

**Ctrl/Cmd+S** или **Save / Сохранить / Guardar** сохраняет содержимое в тот же файл в R2/D1. ID, имя, папка, теги и избранное сохраняются. Запись использует UTF-8; исходные переводы строк и BOM UTF-8 сохраняются. Чтобы правильно открыть старый текст Windows-1251/1252, выберите кодировку в просмотрщике перед входом в редактор. Лимит записи — 4 МБ в UTF-8.

Перед выходом или переключением файла с несохранённым текстом можно сохранить его, отказаться от правок или продолжить редактирование. Закрытие окна и перезагрузка приложения также предупреждают о черновике; смена подключения запрещена до сохранения или закрытия документа. Ошибка записи оставляет текст в редакторе. При изменении версии файла другим устройством сохранение отклоняется, чтобы не затереть чужие изменения. Оригинальный R2-объект заменяется только после подтверждённой записи D1. Во время сохранения можно продолжать печатать: сохраняется снимок на момент нажатия, а более поздние правки остаются несохранёнными.

Документы читаются через S3 SDK в основном процессе Electron, без публичного bucket и настройки CORS. PDF-движок, worker, шрифты, CMap и декодеры входят в сборку; CDN не используется. Лимиты просмотра: **64 МБ для PDF**, **4 МБ для TXT/Markdown**. Для больших или повреждённых файлов доступна кнопка скачивания оригинала в верхней панели. Исходные файлы не изменяются. После обновления полностью перезапустите Electron, чтобы загрузился новый preload/API.

## Кэш миниатюр

Фото, обработанные изображения и кадры видео сохраняются локально в WebP до 640 px по длинной стороне. При повторном открытии папок и после перезапуска готовые миниатюры читаются с диска; оригиналы для этого повторно не загружаются и видео не декодируется заново. Исходные пропорции и длительность видео сохраняются. При замене файла через приложение или изменении коррекции используется новое превью; перенос файла, теги и избранное кэш не сбрасывают.

Кэш расположен в `thumbnails-v1` внутри Electron `userData`, занимает максимум **256 МБ** и автоматически удаляет давно не использованные миниатюры. Он разделён по облачным библиотекам. В настройках видны число превью, занимаемое место и кнопка **Clear thumbnail cache / Очистить кэш миниатюр**. Очистка удаляет только локальные превью; оригиналы R2 и правки D1 сохраняются. Видимые превью остаются на экране, а при следующем открытии создаются заново.

Фото, обработанные изображения и видео создаются через **общую очередь максимум из трёх задач**, включая получение ссылки, загрузку и декодирование. Задачи вне видимой области или из закрытой папки отменяются; отмена доходит до D1/R2, а зависший обработчик изображения перезапускается. Сетевые запросы и создание одной миниатюры ограничены по времени. После временного сбоя выполняются две повторные попытки; кнопка повтора на карточке позволяет попробовать снова без перезапуска приложения.

После создания превью сетка использует маленький WebP вместо декодированного полноразмерного фото. За пределами экрана изображения и Blob URL освобождаются; при возвращении показывается уже подготовленная миниатюра. Временные источники потоков также освобождаются после создания кадра или закрытия просмотрщика и не вытесняют активный видеоплеер. Медленный или недоступный дисковый кэш не блокирует получение превью: чтение имеет ограничение ожидания, запись выполняется в фоне.

Для получения кадра видео используется локальный протокол Electron с потоковыми Range-запросами к R2. HTTP-сервер, скачивание целого видео и настройка CORS bucket не нужны. Если локальный кэш недоступен или повреждён, приложение использует обычный просмотр и восстанавливает превью.

## HEIC и HEIF

Файлы `.heic`/`.heif` открываются во встроенном просмотрщике и получают миниатюры в сетке, списке и галерее. Поддерживаются MIME-типы HEIC/HEIF и импортированные объекты с общим типом `application/octet-stream`; они также включаются в раздел «Фото и видео». Ориентация применяется при декодировании, в коллекциях отображается основное изображение.

Декодирование выполняется локально через libheif/WebAssembly в обработчике изображений, который загружается только при необходимости. Системные HEIC-кодеки, сервер, CDN и изменение CORS не нужны. Лимиты HEIC: исходник до 64 МБ, изображение до 50 Мп (включая фотографии камер «48 MP» с размером 8064×6048). Превью проходят через общую очередь и сохраняются в обычный WebP-кэш до 640 px; повторное открытие папки не требует повторного декодирования HEIC. Фоторедактор и экспорт обработанной копии используют тот же декодер. Скачивание оригинала сохраняет исходный HEIC без конвертации.

Сведения о декодере и лицензии включены в сборку в `dist/licenses/`; см. `THIRD_PARTY_NOTICES.md`. Для повреждённого или неподдерживаемого файла показывается ошибка, остальные миниатюры продолжают загружаться.

## Проекты Pixlr (PXZ)

PXZ открывается в просмотрщике фото. Jellyree собирает изображение в размере холста из слоёв и хранит готовый кадр в кэше просмотрщика. Поддерживаются растровые слои, маски, текст, фигуры, SVG, прозрачность и режимы смешивания. Некоторые эффекты Pixlr, например деформация текста, могут отображаться иначе. Лимит полноразмерного просмотра — 128 МБ и 48 Мп.

Для миниатюры Jellyree читает встроенный WebP через Range-запросы к R2. Если WebP отсутствует или повреждён, миниатюра строится из слоёв. Она сохраняется в общем кэше, а цветная плашка с расширением рисуется поверх неё. Два файла с одинаковым расширением получают один цвет.

## Редактор изображений

Откройте изображение → **Adjust / Коррекция / Ajustar** либо выберите коррекцию в контекстном меню. Desktop использует собственную реализацию; из веб-приложения взят набор инструментов.

- Свет и тон: экспозиция, яркость, контраст, глубина тона, тени и светлые участки.
- Детали: резкость, чёткость, локальный контраст, мягкое свечение, зерно и виньетка.
- Цвет: температура, оттенок, сочность, насыщенность, чёрно-белое, сепия и выцветание.
- Геометрия: произвольный поворот и шаги по 90°, отражения, рамка кадрирования с перетаскиванием и пропорциями, приближение кадра, кисть пластики, горизонтальная и вертикальная полоса растяжения.
- Восемь пресетов, базовая и умная автокоррекция по гистограмме, копирование/вставка правок между изображениями, сброс отдельных разделов и всех настроек.
- История до 80 шагов, Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z, сравнение с оригиналом удержанием кнопки, гистограмма и цветовая индикация потерь в тенях/светах. При выходе с несохранёнными правками предлагается сохранить работу в редакторе или отказаться от изменений.
- **Save adjustments / Сохранить коррекцию** сохраняет только настройки; исходный объект R2 не перезаписывается. Если исходник был заменён во время редактирования, сохранение отклоняется, чтобы не применить правки к другому изображению.
- Экспорт создаёт локальную обработанную копию в JPEG, PNG или WebP с выбором размера и качества. Гистограмма, вспомогательные рамки и подсветка клиппинга в экспорт не попадают.

Оригинал читается через основной процесс Electron, поэтому CORS для R2 не требуется. Обработка пикселей выполняется в отдельном Worker; интерактивное превью ограничено по размеру, экспорт использует тот же алгоритм. Поддерживаются изображения до 64 МБ и 48 Мп. Для экспорта без ограничения размера рабочая область должна быть не более 24 Мп; для больших изображений выберите ограничение размера экспорта. Анимированные изображения обрабатываются как статичный кадр. Миниатюры сохраняются в локальном дисковом кэше.

## Совпадения имён при загрузке

Панель загрузок автоматически открывается при добавлении пачки. Её можно свернуть и продолжать работу. Общий прогресс текущей очереди показан внутри панели, а процент активной передачи — также в верхней строке приложения. Компактные строки разделены на вкладки **In progress / В работе / En curso** и **Uploaded / Загруженные / Subidos**. Завершённые файлы появляются в истории ещё до конца пачки; ошибки и пропуски отмечены отдельно. Список прокручивается по вертикали. Новая очередь после завершения предыдущей начинает собственный общий прогресс.

Для выбора файлов, загрузки папок и drag-and-drop используется общий сценарий. Перед передачей собирается список файлов и количество совпадений, включая одинаковые имена внутри одной загрузки. Сравниваются точные имена активных файлов в одной папке; файлы в корзине и одинаковые имена в разных папках не мешают загрузке.

При совпадении автоматически появляется заметный диалог по центру окна с размером существующего и входящего файла и вариантами:

- **Skip / Проигнорировать / Omitir** — оставить существующий файл и не загружать этот входящий файл.
- **Rename / Переименовать / Renombrar** — загрузить под свободным именем. Предлагается числовой суффикс с сохранением расширения; имя можно изменить вручную. Имена остальных входящих файлов также резервируются, чтобы не создавать новые конфликты.
- **Replace / Заменить / Reemplazar** — заменить содержимое существующего файла, сохранив его ID, папку, избранное, теги и дату добавления. Коррекция фото сбрасывается. Если старый каталог уже содержит несколько файлов с одним именем, диалог сообщает об этом; заменяется самый новый по дате добавления.

Галочка **Apply to all … conflicts** применяет выбранное действие ко всем оставшимся совпадениям текущей загрузки. При массовом переименовании остальные свободные имена подбираются автоматически. В следующей загрузке решение запрашивается заново. Можно отменить оставшиеся загрузки; уже завершённые файлы сохраняются.

Крестик или Escape скрывает диалог совпадения, сохраняя ожидание решения. Для отмены используйте отдельную кнопку отмены оставшихся загрузок. Пока есть незавершённые пачки, смена подключения и индексация R2 недоступны; скачивание и работа с файлами доступны.

При замене сначала создаётся новый объект R2. Только после подтверждённого переключения записи D1 удаляется предыдущий объект. При определённом отказе D1 новый объект удаляется, а старый сохраняется. Если результат записи невозможно подтвердить, объекты сохраняются и приложение сообщает об этом. Ошибка удаления предыдущего объекта после успешной замены отображается как предупреждение.

После обновления файлов основного процесса или preload полностью перезапустите Electron; обновления окна Vite для таких изменений недостаточно.

## Существующие файлы и старый Jellyree

**Индексировать R2** читает объекты под указанным префиксом и добавляет отсутствующие записи в корень текущего каталога. Объекты не перемещаются и не перезаписываются, существующие метаданные остаются. Если префикс пуст, индексируется весь bucket, включая служебные файлы и миниатюры. Индексация не восстанавливает старые альбомы, теги, правки, пользователей и ревизии из MySQL старого сервера. Для переноса этих метаданных понадобится отдельный импорт старой базы; этот клиент использует собственную схему D1.

После индексации объекты управляются этим приложением. Окончательное удаление такого файла удаляет соответствующий объект R2. Для независимого использования старого и нового приложений выбирайте отдельный bucket или префикс.

R2 и D1 не имеют общей транзакции. При определённом отказе записи D1 после загрузки приложение удаляет загруженный объект; при неоднозначном сетевом сбое проверяет наличие записи и сохраняет объект, если подтвердить результат невозможно. При окончательном удалении запись D1 удаляется после успешного удаления R2, чтобы операцию можно было повторить.

## Сборка приложения

После `npm ci` в `desktop/` используйте одну из команд:

```bash
npm run dist:linux  # Linux → AppImage
npm run dist:win    # Windows → установщик NSIS (.exe)
npm run dist:mac    # macOS → DMG
npm run dist       # установщик для текущей ОС и архитектуры
```

Все команды вызывают единый переносимый скрипт `scripts/build.mjs`: он проверяет TypeScript, собирает интерфейс Vite и запускает electron-builder. Команды запускаются без shell-обёрток и работают с путями, содержащими пробелы. Автоматическая публикация отключена через `--publish never`.

Выбор архитектуры и дополнительные режимы:

```bash
npm run dist:linux -- --arch arm64
npm run dist:win -- --arch x64
npm run dist:mac -- --arch arm64      # Apple Silicon
npm run dist:mac -- --arch x64        # Intel Mac
npm run dist:mac -- --arch universal  # один DMG для Intel и Apple Silicon
npm run dist -- --dir                # только распакованное приложение
npm run dist:win -- --dry-run         # показать команды без сборки
npm run dist -- --help
```

Без `--arch` используется архитектура компьютера сборки. Поддерживаются `x64` и `arm64`; `universal` — только для macOS. Скрипт также можно вызвать напрямую из корня:

```bash
node desktop/scripts/build.mjs linux --arch x64
```

Из корня доступны команды `npm run dist:desktop:linux`, `npm run dist:desktop:win`, `npm run dist:desktop:mac`. Например: `npm run dist:desktop:mac -- --arch arm64`.

Результат находится в `desktop/release/`. Имена содержат ОС и архитектуру, например `Jellyree-0.1.0-linux-x86_64.AppImage`, `Jellyree-0.1.0-win-x64.exe`, `Jellyree-0.1.0-mac-arm64.dmg`, поэтому сборки разных архитектур не перезаписывают друг друга.

Для DMG нужен Mac; при попытке обычной сборки macOS на другой ОС скрипт сразу выдаст понятную ошибку. Windows штатно собирается на Windows, Linux — на Linux. Для кросс-сборки Windows на Linux/macOS требуется отдельно подготовленное окружение electron-builder с Wine. [Ограничения кросс-сборки](https://www.electron.build/v26/docs/features/multi-platform-build/).

### Сборка всех ОС через GitHub Actions

Workflow `.github/workflows/desktop-build.yml` запускается вручную: **Actions → Build desktop installers → Run workflow**. После загрузки workflow в репозиторий он создаёт четыре независимые сборки на соответствующих ОС:

- Linux x64 → AppImage;
- Windows x64 → EXE;
- macOS x64 → DMG для Intel;
- macOS arm64 → DMG для Apple Silicon.

В каждой задаче выполняются `npm ci`, тесты и тот же скрипт сборки. Установщики доступны в **Artifacts** выбранного запуска в течение 14 дней. Workflow не создаёт GitHub Release. Подпись приложения, notarization и автоматическое обновление не настроены; CI отключает автоматический поиск сертификата подписи. Для Linux запускайте приложение обычным пользователем с работающей Chromium sandbox.

## Проверки

```bash
npm test             # D1/SQLite, папки, поиск, корзина, ошибки загрузки, ключи
npm run build        # TypeScript + production Vite
npm run test:smoke   # реальный Electron + UI-тесты с имитацией Cloudflare
npm run test:editor  # обработка пикселей, геометрия, история, сохранение и экспорт в Electron
npm run test:thumbnails # дисковый кэш фото/видео и повторное открытие без R2
npm run test:thumbnail-stress # массовые фото, зависшие S3/worker/cache, отмена и повтор
npm run test:heic     # реальные HEIC: цвета, ориентация, основной кадр, кэш и экспорт
npm run test:pxz      # миниатюры PXZ, слои, плашки и кэш
npm run test:video   # скорость, точный PNG, сохранение в папку и на компьютер
npm run test:documents # PDF: страницы/масштаб/текст; TXT: поиск/кодировки; безопасный Markdown
```

Для smoke-теста нужен графический сеанс (или Xvfb на Linux) и установленный Chrome. По умолчанию используется `/usr/bin/google-chrome`; другой путь передайте в `CHROME_PATH`. Тест запускает production-сборку, поэтому сначала выполните `npm run build`. Тест не использует настоящие Cloudflare-реквизиты. Скриншоты пишутся в системный временный каталог.

## Устройство

- `electron/main.mjs` — окно, проверка отправителя IPC, диалоги ОС и ограниченный API операций.
- `electron/preload.cjs` — sandboxed bridge с `contextIsolation`; Node API недоступны интерфейсу.
- `electron/config.mjs` — валидация реквизитов и шифрованное хранение.
- `electron/d1.mjs` — прямой HTTPS-клиент Cloudflare D1 REST API, параметризованные SQL-запросы.
- `electron/library.mjs` — файловые операции, S3/R2, D1, загрузка папок, индексация.
- `electron/schema.sql` — независимая схема D1.
- `electron/locales.mjs` и `src/i18n.ts` — общий словарь и реактивный выбор языка.
- `electron/upload-conflicts.mjs` — обмен запросами и решениями по конфликтам через IPC.
- `src/UploadConflictDialog.vue` — диалог совпадающих имён.
- `src/` — интерфейс Vue; сетевые операции выполняются через bridge, без ключей в renderer.

Использованы официальные API: [D1 REST query](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/), [R2 / AWS SDK v3](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/), [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage).
